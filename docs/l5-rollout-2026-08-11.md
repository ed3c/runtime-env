### What a consumer must own

Managing a consumer-local `.env` is **not** the integration mechanism. A
consumer must not create a second dotenv authority. The host owns the canonical
`/Users/neon/runtime-env/.env`; each consumer owns only its versioned contract
and code boundary:

1. generated `.runtime-env/` profile/module projections pinned to the immutable
   runtime commit;
2. fixed workload adapters and declared execution-plane or broker boundaries;
3. public-seam tests plus the repository's normal hook/CI gate;
4. an installed CLI whose revision matches the projection;
5. for L5, a consolidated receipt bound to the exact consumer and runtime
   commits.

A projection supplies names, metadata, and safe defaults. It does not supply
secrets, authenticated browser state, model compute, or another execution
plane. Those remain host capabilities.
